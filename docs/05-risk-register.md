## سیاست بازگشت به عقب پروژه

۱. **وضعیت سالم مرجع**: هر وضعیتی که در آن `npm run build` سبز است و آزمون دود مسیرها پاس می‌شود.
۲. **قبل از هر تغییر پرخطر**: اجرای `npm run build` و ثبت نتیجه؛ اگر بعد از تغییر بیلد شکست، تغییر برگردانده می‌شود.
۳. **تغییرات برگشت‌پذیر**: تغییرات فایل‌محور و بدون اثر بیرونی هستند؛ بازگشت با بازگردانی همان فایل انجام می‌شود.
۴. **یک عملیات بازگشت‌ناپذیر وجود ندارد**، چون هیچ انتشار، حذف داده یا مهاجرت پایگاه داده‌ای در دامنه نبوده است.
۵. **حذف `.next` همیشه بی‌خطر است**: کش بیلد است و با `npm run build` بازساخته می‌شود.

## آزمون بازگشت به عقب

آزمون R-4 و R-9 به‌صورت واقعی و نه فرضی انجام شد: طراحی «شکست یک زنجیره» با تست خودکار پوشش داده شد و رفتار مشاهده‌شده مطابق انتظار بود (پرچم `degraded` بدون تبدیل به خطای کامل). آزمون بازگشت کامل نسخه با اجرای مجدد زنجیره کامل دروازه‌ها روی همان درخت انجام شد و هر شش دروازه سبز ماند.
